# V1.3.4 Reliability & Coverage Hardening — 实施计划（Lead 权威版）

> 本文件是 V1.3.4 的实施基线，吸收用户最终指令与 V1.3.4 方案审核报告（B1–B5）的修订。
> 状态权威文件：`.uiux/status/v1.3.4.json`（本文件只描述计划，不记录运行状态）。

## 1. 目标与验收等级

- 目标版本：`1.3.4`（兼容 1.3.3 安装/契约/语义）。
- 最终交付：`dist/uiux-suite-1.3.4-win64.zip` + SHA256SUMS + RELEASE_MANIFEST + 完整证据链 + 中文验收报告。
- 验收等级：按 V1.3.3 验收报告定义（A/B/C）；本轮**不预设 A 级**，以实际证据定级；无外部信任锚时最高 `ISOLATED_SESSION / INDEPENDENCE_UNVERIFIED`，不签发 `INDEPENDENT_REVIEW_PASS`。

## 2. 任务 DAG（用户最终修订版）

```
TASK-00 版本化/双契约（P0，最先）
  ├─> TASK-01 Fixture 最小集（依赖 TASK-00 契约基础）
  ├─> TASK-03 Coverage/G6（依赖 TASK-00）
  │     └─> TASK-02 Inventory（依赖 TASK-00 + TASK-03 接口；独立部分可与 TASK-01 并行）
  │           ├─> TASK-04 缺陷归因（依赖 TASK-01 + TASK-02）
  │           ├─> TASK-05 高风险验证（依赖 TASK-01 + TASK-02 + TASK-03 证据契约）
  │           └─> TASK-08 Report Facts/Linter（依赖 TASK-02 + TASK-03）
  └─> TASK-06 Runtime Binding（依赖 TASK-03 证据契约）
TASK-07 外部可信来源（Phase C，依赖 CI/发行机制；非本地正式发行硬性前置）
```

允许并行条件：接口契约冻结且写作用域不重叠。禁止循环依赖。

## 3. 分期

### Phase A → `1.3.4-rc1`
TASK-00、TASK-01、TASK-03、TASK-02、R0–R4/R8、基础 report-facts、全量回归、安装/升级/回滚、New Manga 隔离试点 audit+verify。
RC1 通过后自动进入 Phase B。

### Phase B → `1.3.4` 正式版
TASK-04、TASK-05、TASK-06、TASK-08、R5–R7/R9、正式回归、最终验收、正式打包。

### Phase C（可选）
TASK-07：GitHub Actions 可验证来源证明（CI 构建来源 ≠ 独立 Reviewer 通过）。不可达则 `DEFERRED`，不阻塞正式版。

## 4. 关键设计裁决（ADR 摘要）

| ID | 裁决 | 理由 |
|---|---|---|
| ADR-134-01 | v1.3.3 Schema 全量保留只读；新增 v1.3.4 全套 Schema（26 份），`$id` 与文件名带 v1.3.4 | 历史契约不可变；双版本自洽；引用可解析 |
| ADR-134-02 | `contracts.py` 增加版本分派：按 instance/schema 的 `schema_version` 选择版本；无版本字段时 fail-closed（除非显式 `--schema-version`） | B1 要求禁止静默混用 |
| ADR-134-03 | `finalize` 按输入 `task-request.schema_version` 分派：v1.3.3 → legacy 语义（精确复现 PARTIAL/G6 UNVERIFIED）；v1.3.4 → 新语义 | 强制兼容用例 |
| ADR-134-04 | v1.3.4 coverage 扩展：保留 `test_state` 五枚举；新增 `disposition` 枚举（原因码）与可选 `scope_ref`；聚合规则见 GATE_MAP | B3：不替换旧语义 |
| ADR-134-05 | Inventory 采用 declared scope：自动发现 → 人工确认 → 冻结哈希 → 覆盖映射 → 独立复核；100% 仅对 declared scope 映射率 | B2 |
| ADR-134-06 | Fixture 与环境自检先于任何 P0/P1 定级；环境异常不得计入产品缺陷 | TASK-01 |
| ADR-134-07 | 高风险验证分只读模式与隔离验证模式；隔离模式必须绑定可恢复沙箱与合成数据 | TASK-05 |
| ADR-134-08 | Runtime Binding 三级可信：build-provenance > artifact-hash > runtime-marker；仅允许声明实际达到的级别 | TASK-06 |
| ADR-134-09 | Report Facts 为机器可读事实源；Linter 校验 facts 与证据，Markdown 仅展示 | TASK-08 |
| ADR-134-10 | R0–R9 复用 G0–G5 事实，不产生第二套权威证据 | 用户 Gate 规则 |
| ADR-134-11 | 轻量多 Agent：DSH Lead + 独立 teammate + 共享任务板；不 bootstrap 完整 `.orchestrator` | 用户 §五 |
| ADR-134-12 | 同模型家族披露：独立会话 + 独立数据 + 独立采集 + 独立基线；不冒充跨模型/外部签发 | 用户 §五 |

## 5. 版本与兼容约束

- 1.3.3 安装、1.3.3 suite-link、1.3.3 manifest、1.3.3 证据输入必须继续可读。
- `enums.v1.3.3.json` 保留；新增 `enums.v1.3.4.json`（新增枚举只增不改）。
- `mode-gate-policy.v1.3.3.json` 保留；新增 `mode-gate-policy.v1.3.4.json`（如需要）。
- 发行包文件名：`uiux-suite-1.3.4-win64.zip`；不得覆盖 `dist/uiux-suite-1.3.3-win64.zip` 与 tag `v1.3.3`。
- 版本号落点：`runtime/uiux_engine/__init__.py`、`scripts/setup_skill.py`、`scripts/build_release.py`、`skills/*/suite-link.json`（安装时生成）、`RELEASE_MANIFEST.json`（构建时生成）。

## 6. 质量与安全红线

1. 不修改 New Manga 原项目与 `G:\AI\uiux-workbench-copy` 业务代码/数据。
2. 不覆盖 v1.3.3 tag/发行包/历史证据。
3. 不删 UNVERIFIED 换 PASS；不降低 required runtime level；不伪造独立性。
4. 不引入只对 New Manga 有效的硬编码。
5. 不把 Mock/静态推断写成 Native 证据。
6. 发行包排除私有证据（`evidence/`、沙箱、测试数据）。
7. 所有 Gate 结果由证据派生，可机械复算。
